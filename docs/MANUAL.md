# PlantGuard ML Layer — Beginner Manual

## 0. What you are building

The production flow is:

1. Real field photo
2. SAM 2.1 segments a leaf
3. DINOv2 leaf filter rejects bad/non-leaf crops
4. DINOv2 disease classifier predicts the PlantVillage class
5. SegNeXt predicts disease pixels
6. XGBoost predicts a 0–100 severity value from measurable features
7. Transformer-CAM provides an explanation heatmap
8. Mahalanobis OOD + classifier confidence produce a reliability signal
9. FastAPI exposes one clean endpoint to the application

### What is trained?

| Component | Training in this repo? | Notes |
|---|---|---|
| SAM 2.1 | No, initially | Use official pretrained checkpoint. Fine-tuning is optional and should be a separate research experiment. |
| DINOv2 leaf filter | Yes | Binary leaf/non-leaf head. |
| DINOv2 disease classifier | Yes | Trained on PlantVillage. |
| SegNeXt | Yes | Fine-tune official SegNeXt implementation on PlantSeg. |
| XGBoost severity | Yes | Requires numeric severity labels. |
| OOD | Fit, not neural training | Mahalanobis statistics over DINO embeddings. |
| Transformer-CAM | No | Explanation generated at inference. |

## 1. Hardware

### Recommended training machine

- NVIDIA GPU with >= 12 GB VRAM for DINO training.
- 16 GB RAM minimum; 32 GB+ is preferable.
- SSD with at least 50 GB free for PlantVillage + caches; more for PlantSeg.
- Your high-end PC/Colab GPU is the appropriate place for training.

### Application laptop

Your CPU-only laptop can run the API, but SAM 2.1 + SegNeXt will be slower. Keep the FastAPI boundary model-agnostic so you can move heavy inference to a GPU server later.

## 2. Install Windows prerequisites

Install:

1. Git
2. Miniconda or Anaconda
3. VS Code
4. Python is supplied through the conda environment; do not install random system Python packages globally.
5. NVIDIA driver if you are using an NVIDIA GPU.

VS Code itself is enough for editing/running. No manual PATH editing is normally needed if you use **Anaconda Prompt** or the VS Code terminal after activating conda.

## 3. Create the environment

Open Anaconda Prompt:

```powershell
conda create -n plantguard-ml python=3.11 -y
conda activate plantguard-ml
cd <YOUR_FOLDER>\plantguard_ml
```

### CPU-only

```powershell
pip install -r requirements-cpu.txt
pip install -e .
```

### NVIDIA GPU

First install PyTorch using the command generated by the official PyTorch installer page for your driver/CUDA combination. Then:

```powershell
pip install -r requirements-gpu.txt
pip install -e .
```

Verify:

```powershell
python scripts/01_check_environment.py
```

You want `CUDA available: True` on the training machine.

## 4. Download PlantVillage

Use the official PlantVillage/Hugging Face dataset. The upstream dataset provides 54,306 images and exposes `leaf_id`; its recommended split preserves leaf grouping to avoid leakage.

```powershell
pip install datasets
python scripts/02_prepare_plantvillage_hf.py
```

This downloads the color configuration and writes:

`data/processed/plantvillage_hf/manifest.json`

Do not create a random image-level train/test split for your final research result. Images of the same physical leaf can otherwise appear in both sets.

## 5. Train DINOv2 disease classifier

Default backbone: `dinov2_vitb14`.

```powershell
python scripts/03_train_dino_disease.py
```

Expected artifact:

```text
artifacts/dino_disease/dino_disease_classifier.pt
artifacts/dino_disease/classes.json
```

The model is a DINOv2 pretrained visual backbone + trainable classification head. Initially the backbone is frozen. If validation performance is insufficient on your field validation set, you can later unfreeze selected final blocks; do not do this just to increase a benchmark number without checking field generalization.

### Important field-validation step

PlantVillage is mostly controlled/background imagery. It is useful for learning disease categories but is not a substitute for a real-field test set. Before deployment, collect a separate real-field dataset with:

- different lighting
- multiple phones/cameras
- different backgrounds
- multiple leaf orientations
- healthy leaves
- unrelated objects/non-leaf images
- disease stages
- visually similar diseases

Keep that dataset completely outside training.

## 6. Build the DINOv2 leaf filter

The filter is intentionally separate from disease classification. It answers: "Does this crop look like a valid leaf crop?"

### Bootstrap dataset

Create or obtain a folder containing obvious non-leaf images. Then:

```powershell
python scripts/05_make_leaf_filter_dataset.py --plantvillage <PLANTVILLAGE_PATH> --negative <NON_LEAF_FOLDER>
```

You should end up with:

```text
data/processed/leaf_filter/
  leaf/
  non_leaf/
```

Then train:

```powershell
python scripts/04_train_dino_leaf_filter.py
```

Artifact:

`artifacts/dino_leaf_filter/dino_leaf_filter.pt`

For the final research dataset, add real-field negatives such as soil, sky, pots, hands, stems without leaves, tools, walls, multiple leaves, blur, and background clutter. The bootstrap set is not final ground truth.

## 7. Install SAM 2.1

```powershell
python scripts/09_setup_sam2.py
```

Download the official SAM 2.1 Base+ checkpoint and place it at:

`artifacts/sam2/sam2.1_hiera_base_plus.pt`

The official repository lists Tiny, Small, Base+, and Large checkpoints. Base+ is the default in this project because it balances quality and compute better than blindly using Large.

Do NOT retrain SAM 2.1 for the first end-to-end integration.

If later you have a manually annotated leaf-segmentation dataset, SAM 2.1 provides official fine-tuning code, but the upstream training documentation assumes high-end multi-GPU hardware for its example workflow.

## 8. Prepare PlantSeg

PlantSeg is the disease pixel-segmentation dataset. The project reports more than 11,400 in-the-wild images and 115 diseases. The latest public releases are large; use the current Zenodo release linked from the official project.

Download/extract PlantSeg manually into something like:

```text
data/raw/plantseg/
```

Then inspect it:

```powershell
python scripts/10_prepare_plantseg.py --root data/raw/plantseg
```

### Why this is a manual checkpoint

PlantSeg has had multiple public releases and annotation packaging changes. The official repository documents its MMSegmentation-based workflow. Do not blindly rename folders from an old tutorial.

Your final segmentation dataset must provide:

```text
image -> pixel mask
```

with at least:

- class 0 = background/non-disease
- class 1 = disease

If you want multi-class disease segmentation instead, change `num_classes` and the label mapping consistently.

## 9. Install official SegNeXt

```powershell
python scripts/08_setup_segnext.py
```

The official SegNeXt repository is based on MMSegmentation. Use one of its supplied semantic-segmentation configs as the starting point and adapt the dataset paths/classes to your exact PlantSeg release.

Edit:

`configs/segnext_plantseg.py`

The repository includes a current config targeting the common PlantSeg `images/{train,val,test}` + `annotations/{train,val,test}` layout. If your downloaded release differs, run the inspection script and change the three path fields at the top of `configs/segnext_plantseg.py`.

### Train

```powershell
python scripts/11_train_segnext.py --config configs/segnext_plantseg.py
```

Put the best checkpoint at:

`artifacts/segnext/best.pth`

### SegNeXt target

Input: the leaf crop from SAM 2.1.

Output: disease mask aligned with the leaf crop.

Do not train SegNeXt on the original full field image if your runtime contract says that it receives leaf crops. Train and validate it with the same crop geometry used in inference.

## 10. Severity model

XGBoost cannot learn a meaningful severity number without a target.

You need a CSV:

```text
image_id,disease_area_pct,leaf_area_px,disease_components,mean_disease_prob,edge_contact_pct,leaf_count,classifier_confidence,severity
...
```

`severity` should be a human/annotation-derived target on a defined 0–100 scale.

Then:

```powershell
python scripts/07_train_severity.py --csv data/processed/severity_labels.csv
```

Artifact:

`artifacts/severity/xgb_regressor.json`

### Very important

Do not claim that an XGBoost model trained only on segmentation-derived pseudo-labels is a real disease severity model. Pseudo-labels are useful for an engineering smoke test, not a validated agronomic severity score.

## 11. OOD / reliability

After DINO classifier training:

```powershell
python scripts/06_fit_ood.py
```

Artifact:

`artifacts/dino_disease/ood.npz`

Runtime reliability should combine at least:

- classifier confidence
- OOD distance
- leaf-filter score
- SAM mask quality/area sanity checks
- segmentation confidence if available

Do not convert this into a fake single percentage unless you calibrate it against a held-out reliability dataset.

## 12. Explainability

The project provides `TransformerCAM` for gradient-based transformer explanations. This is deliberately named Transformer-CAM rather than pretending DINOv2 is a CNN Grad-CAM model.

For research, compare explanations against:

- disease mask
- human-marked diseased regions
- occlusion tests

An attractive heatmap alone is not proof that the model is reasoning correctly.

## 13. Optimize/export models

### ONNX

```powershell
python scripts/12_optimize_models.py
```

The script exports the DINO classifier/filter to ONNX and validates the graph with ONNX Runtime.

### CPU dynamic quantization

```powershell
python scripts/15_optimize_cpu.py
```

Treat this as an optimization experiment. Measure accuracy and latency before replacing the FP32 artifacts.

### SAM 2.1

For GPU inference, benchmark the official SAM 2.1 compile options before doing custom graph conversion. The official repository supports compiling the image encoder/full video model paths for speedups.

### SegNeXt

Keep the trained PyTorch/MMseg checkpoint as the research reference. Add ONNX/TensorRT conversion only after the exact SegNeXt config/checkpoint is fixed and you have numerical parity tests.

## 14. Artifact manifest

After all final artifacts exist:

```powershell
python scripts/16_write_artifact_manifest.py
```

This writes SHA-256 hashes so the application layer can verify exactly which model version it is using.

## 15. Run FastAPI

From the repository root:

```powershell
python scripts/13_run_api.py
```

Open:

`http://127.0.0.1:8000/docs`

Check:

```text
GET /health
POST /v1/inference
```

The application should call only `/v1/inference`.

## 16. Test an image

```powershell
python scripts/14_smoke_test.py --image <REAL_FIELD_IMAGE.jpg>
```

A successful response contains status, disease prediction/confidence, leaf area, SAM score, disease area, severity, OOD information, and latency.

## 19. Integration contract for your existing PlantGuard application

Do not copy this repository's model internals into React/backend application code.

Use:

```text
PlantGuard App
     |
     | HTTP multipart image
     v
FastAPI /v1/inference
     |
     +-- SAM2
     +-- DINO leaf filter
     +-- DINO disease classifier
     +-- SegNeXt
     +-- XGBoost
     +-- reliability/OOD
     +-- explanation
     |
     v
JSON response + optional artifact paths
```

This keeps the application model-agnostic. You can replace DINO, SegNeXt or XGBoost later without rewriting the frontend/orchestrator.

## 20. Research warning

PlantVillage is controlled and PlantSeg is in-the-wild disease segmentation data. A high PlantVillage classification score does not establish real-field diagnostic accuracy. Treat the real-field held-out evaluation as the deployment gate.
